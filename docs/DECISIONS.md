Auth0/CIMD stays in place, DCR stays disabled, and no custom authorization server is introduced.
- Preserve stateless finite Streamable HTTP on Netlify: SDK 1.32.1, Zod 4, jose 6.2.12, request-local server/transport, no session IDs or persistent GET SSE. Retain RS256, exact issuer/audience, expiry, user-subject, and M2M rejection checks.
- Expose exactly ping/read/upsert. Ping/read require `dashboard:read`; upsert requires `dashboard:write`. Check actual invocation scope before forwarding and again inside callbacks. HTTP 403 and OAuth tool metadata identify missing scope. Resource metadata advertises the initial read scope; write is explicitly advertised on the upsert tool for step-up authorization. Grant write only to the specific ChatGPT CIMD app.
- Resource remains the existing Auth0 API Identifier (site origin), with root/path-specific protected-resource metadata. Preserve exact issuer trailing slash. Publish top-level OAuth `securitySchemes` plus compatibility `_meta`.
- Hardcode five existing dashboard endpoint URLs and credential prefixes. Reject unknown dashboard IDs and extra input fields. No caller routing, credentials, replace mode, home-board, or config database.
- Read forwards server-side PIN authentication, returns at most 50 items and compact counts/timestamp, and omits history. Upsert forwards server-side Bearer authentication and only `{ items }`, returning a compact receipt. Existing APIs and Blobs remain authoritative and unchanged.
- Upserts are not replay-idempotent: repeated observations affect `seenCount`, `lastSeenAt`, `runs`, and `runHistory`. Never automatically retry uncertain writes. Timeouts/network errors, malformed successful responses, and non-auth HTTP failures conservatively report write uncertainty; downstream authentication failures are reported as rejected. Suppress downstream bodies and private errors.
- Log only request ID/status/duration; never log OAuth claims, tokens, dashboard credentials, or request bodies. Store all downstream credentials in Functions environment variables on the MCP site.
- Original Slice 1B deployment decision: the connected Netlify tool supported inspection but not Git deployment/environment updates; operator deployment was scoped to the existing MCP site. That deployment gate is now owner-confirmed complete. Slice 4A needs no deployment/site configuration changes and no merge to main.

## Slice 4A — data contract and scoring

- Define the additive contract in [DATA_CONTRACT.md](DATA_CONTRACT.md). All new fields are optional; preserve existing display/source fields and arbitrary items. Current API/MCP schemas pass these additions through, so no code/schema validation change or generic scoring layer is needed.
- Never fabricate dates, pay, prices, distances, or evidence. Keep original text; omit unknown additions. Hourly bounds remain source-faithful; annual salary is never converted into persisted hourly source data. Unknown evidence contributes 0 to an assessed rubric; an unassessed item has no score, not a zero score.
- Freeze four discrete 100-point v1 rubrics; recognized numeric scores use `scoreVersion: 1`. Job Rates rewards credible $75+/hr W2 most highly and uses disclosed lower bounds against the $65–$75/hr W2 target. Eligibility/actionability is separate: scores cannot erase known blockers, unverified Christian affiliation, or vehicle condition uncertainty.
- Provenance stays additive: `backfilled` identifies genuine imports; `originallyObservedAt` requires a genuinely known original observation instant. `firstSeenAt` remains first observed by Dashboarda persistence. No fake history, counter resets, reconstructed past price/rate trends, or persistence redesign.
- Preserve identity before enrichment. Incoming `_key` does not override endpoint keys; changing higher-precedence identity fields or fallback contents can duplicate records. Slice 4B snapshots full state, reviews a source-grounded manifest, holds unsafe identity matches, pilots safe upserts, and reconciles uncertain writes without automatic retries.
- Product hierarchy: **DO NEXT → ranked actionable queue; NOTICE → one dashboard-specific visualization; EXPLORE → full searchable/filterable dataset**. Define ordering/missing-data behavior now; shared layout waits for 4C and individual decision UIs for 4D–4H.
- Track natural scheduled-run verification separately from imports. Slice 4A is completed documentation-only contract/scoring work; no backfill, stored-record edits, runtime scoring, producer prompt edits, ranking/chart UI, database, or API/MCP changes were part of 4A.

## Slice 3B — scheduled-run observability

- Every scheduled Dashboarda task must attempt exactly one `dashboard_upsert` per run. If qualifying items exist, send them in one batch; if none exist, send `items: []`. Retain task-specific filtering and notification behavior.
- A zero-item upsert is a successful synchronization event: advance run metadata/history without creating records or changing existing item observations. Existing five `/api/state` handlers already implement this; MCP accepts 0–50 objects rather than blocking empty arrays.
- Never retry an uncertain write, including an empty one. Upserts remain non-idempotent; the one-call rule is an orchestration requirement, not an exactly-once delivery guarantee. Failed/skipped writes remain unproven syncs.
- Keep exactly ping/read/upsert, fixed five-dashboard routes, OAuth scope separation, downstream credentials, existing persistence, and bounded reads. No new run/log tool, queue, database, backfill, scoring or UI work.
- All five task prompts were amended, and the 3B MCP update was deployed and naturally production-proven on 2026-10-10. Local Prospects and Job Rates still await natural receipts; their verification may proceed on their regular schedules and does not block controlled 4B backfill. Historical imports cannot close those verification gates. All accepted 4A decisions remain in force.

## Slice 3D — scheduled write outcomes and semantics

- Use **Successful syncs** and **Last successful sync** consistently in all five task dashboards. A sync means a persisted Dashboarda state update, including a zero-item batch or manual/historical write, not a scheduled task execution or successful tool acknowledgment. `runs` remains the existing read/modify/write increment; it is not an atomic/exactly-once ledger. `updatedAt` is the server processing time captured before persisting that state, not an exact commit-completion time. Do not rename stored fields or change persistence/MCP.
- 3C confirmed Empower/KFORCE persistence and recovered outputs reporting authorization/safety-blocked recruiter writes. The audit's execution/sync timestamps diverged; complete underlying tool logs were unavailable. **Allow all actions** is already configured for Dashboarda per Tucker; do not assume a missing plugin setting, assert an unproven OAuth scope cause, or work around platform controls. UI labels clarify evidence; they do not repair blocked writes.
- Preserve the exactly-one-upsert-attempt rule, including `items: []`, and **never automatically retry an uncertain write**. A persisted write with a lost/malformed response can have an uncertain caller outcome. Rejected/blocked attempts before persistence do not count; an uncertain outcome does not prove that nothing was written.
- The smallest orchestration change is a failure-notification override for **all five** scheduled tasks, including runs with no qualifying items. Keep task-specific filtering and ordinary result summaries. This amendment is **proposed, not applied** in 3D; no scheduled task, permission, or production record was changed.

## Slice 4C — shared UI and Refresh

- Keep the five independent static task sites and their existing authenticated `/api/state` GET. Share vanilla JS/CSS in `shared/`, copy to each app with `npm run sync:dashboards`, and commit the generated site-local assets. Each task-app build also synchronizes its own assets; existing publish directories, functions and authentication remain unchanged. Home Board is outside this slice. No framework/runtime dependency or shared hosted asset service.
- **DO NEXT** is a top-three **record-review queue**, not an apply/buy/contact recommendation. Require an explicitly active stored status (`new`, `open`, `active`, `pending`, `unresolved`, `todo`, `needs-action`, `action-required`) plus minimum supporting fields. Email also needs an action, subject and source message ID/HTTP(S) URL; test-category email is excluded. Prospects need business/location/workflow/hypothesis; jobs need employer/role/source URL/fit text; Jeep needs vehicle/source URL/condition. These are conservative presentation checks, not independent verification of source truth, unresolved status or eligibility. Missing/unrecognized/inactive statuses or incomplete records remain in EXPLORE. Do not infer an active status from the former default `new` badge.
- Rank the review queue by supplied Email high/medium/low/unprioritized, then valid explicit `dueAt` ascending; do not recalculate or persist urgency. Other sites recognize integer 0–100 scores only with numeric `scoreVersion:1`, sort descending, then show a labeled unscored group. Assessed zero precedes unassessed; malformed/other-version scores remain unscored. Tie-break by valid `lastSeenAt` descending (unknown last), then stable identity in Unicode code-point order. Preserve endpoint key precedence/fallback semantics; never rewrite identities or metadata.
- **NOTICE** supplies only factual assessment/unassessed/historical-import counts across the saved dataset in 4C. **EXPLORE** retains every item, all existing display columns, arbitrary stored fields in expandable details, text search, status and assessment filters. Missing status is “Not supplied,” not “new.” Historical imports have a visible badge. No score computation, legacy-field normalization, hourly conversion, source date inference or data migration. Domain eligibility/action policies and each dashboard's single NOTICE visualization remain 4D–4H; a high score does not certify an opportunity's eligibility or a vehicle's safety.
- Refresh makes one explicit PIN-authenticated GET with `cache:"no-store"` and a 15-second abort timeout. Guard concurrent clicks and show disabled **Refreshing…**, `aria-busy` and live feedback. Success distinguishes initial/unchanged/changed state and updates browser **Checked at**; server **Last successful sync** remains the returned `updatedAt`. Refresh never calls MCP upsert, triggers a task or changes a persisted counter. It does not attest source-check coverage or scheduled execution.
- Reject invalid state envelopes/items/run metadata and unreadable JSON before replacing the current view. HTTP/network/auth/timeout failures preserve the last good state and Checked at, visibly identify stale retained data, and never display private response/error bodies. Initial failure/cancelled PIN retains “not loaded” placeholders rather than claiming zero results. A 401 clears only the browser's saved PIN and invites a user-initiated Refresh to enter it again; no automatic retry or permission/config change. Unavailable local storage must not prevent an authorized read.
- Escape arbitrary stored text and permit only absolute HTTP(S) source links with `rel="noopener noreferrer"`. Provide visible keyboard focus, labeled controls, live Refresh feedback, mobile stacked rows and a review link that clears filters, opens the selected record and moves focus to its details. No animations, charts or production writes are needed for the shared foundation.
